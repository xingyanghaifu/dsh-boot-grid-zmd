# 明日方舟：终末地（zmd）视觉语言调研

> 一句话结论：终末地不是「深色赛博 HUD」，而是**工业调度台 + 印刷图纸**两种表面共用一套 token——石墨底/纸面底二选一，1px 结构线搭骨架，信号黄只做「需要被看见的那一处」，全直角、全大写、等宽数字。
>
> **取证边界（先说清楚）**：本机沙箱无外网直连（`curl`/`Invoke-WebRequest` 均超时），`web_fetch` 只回文本、拿不到官网 CSS 与截图，因此**官网官方色值没有直接从官网源码取到**。所有色值来自本地源码变量（A 级）或本地 PNG 像素取样（B 级）；C 级为第三方文档/二手报道，已逐条标注，凡属推断都写明「推断」。

| hex | 用途 | 占比建议 | 来源 |

| `#fff500` | 官网同族更高饱和档；只用于品牌标记与主 CTA | ≤2% | C https://cdn.jsdelivr.net/npm/dsh-theme-endfield@1.2.3/docs/design-language.md |
| `#e46f24` | 方舟/莱茵系强调橙；**不是终末地色**，仅作「同族不同作」对照 | — | A `preview-rhine-line.html:9` + B 取样 |
| `#f0893e` | 同一橙色在近黑底上升亮后的档位 | — | B 取样 `splash-dark.png` |
| `#ff3b30` / `#d9822b` / `#2f9e44` | 错/警/成（推断值，需按 AA 4.5:1 复核后再用） | ≤1% | C 同上第三方文档 |

**取样方法与实测值**（可复现）：
- 方法：`Add-Type System.Drawing` → `Bitmap.GetPixel` 逐像素统计小方块区域的颜色频次（脚本见本次会话 pwsh 调用）。
- `ref/rhine/splash-light.png` 40×40 @(0,0)：`#e6e5e1` ×966 → 纸底；12×12 @(88,14)：`#e46f24` ×36 → 强调色；@(36,144)：`#141414` ×35 → 墨黑。
- `ref/rhine/splash-dark.png` 40×40 @(0,0)：`#0f0f11` ×858 → 石墨底（**与 `index.html:8` 的 `#0f1419` 同族，差在 R/B 通道几个值**）；12×12 @(88,14)：`#f0893e` ×36。
- 危险条纹区域 40×14 @(1148,764) 只出现两种主色：`#141414` ×124 与 `#e46f24` ×116 → **条纹是「强调色 + 底色」两色硬切，无渐变**。

**占比依据**：第三方主题包的实测截图统计为「黄像素 5.47%（纸面亮）/2.51%（石墨暗）」（C 同上文档）。本地样片的黄只出现在 14px 竖轨、58px 主读数、四条角标、两条 6px 危险带、若干 `<b>`——目测同量级，故取 2–6%。

**用色规则**（A 级行为可从源码验证，C 级为原则）：
1. 黄不做底色填充（整份 `index.html` 无一处黄底黑字区块）；纸面系里黄字压纸底只有 1.07:1，必须换深档（C）。
2. 同一色在亮/暗底需要不同取值：橙 `#e46f24` → 暗底 `#f0893e`（B 实测）；黄 `#fbfb46` → 暗底直接用原值（A `:10` 只有一档，说明它本来就是为深底选的）。
3. 单一强调色，状态色另立（错/警/成），互不替代（C）。

**数字**：`font-variant-numeric: tabular-nums`（A `:113`）+ 手工补零 `padStart`（`:469,580`）+ 固定小数位 `.toFixed(1/2)`（`:583-589`）。读数形如 `0x0000`、`000.0°`、`2.41 GW`——**单位与值分离，单位用 dim 色**（`:344,351`）。

## 3. 线条语言

| 元素 | 规格 | 来源 |
|---|---|---|
| 结构细线 | 1px，`rgba(236,237,237,.12)`，四边内缩 58px | A `index.html:130,134-139` |
| 角标 | 12×12，只画 2px 的两条边（L 形），四角错峰 60ms | A `:143-151` |
| 危险条纹 | 高 6px，`45deg`，周期 9px/9px，黄+底硬切，透明度 .85 | A `:155-159` |
| 背景网格 | 主网 64px（白 4.5%），细网 16px（白 2.2%），径向 mask 渐隐（主 25%→78%，细 10%→65%） | A `:36-49` |
| 扫描线纹理 | `repeating-linear-gradient` 1px 亮/3px 空，白 2.5%，全屏覆盖 | A `:27-29` |
| 暗角 | `radial-gradient(120% 90% at 50% 45%, transparent 28%, rgba(0,0,0,.62))` | A `:30-33` |
| 拓扑线 | 3 簇，16/18/12 环，半径步进 30px，三重正弦扰动，透明度 .035+.028 呼吸 | A `:488-492,494-520` |
| 示波器网格 | 15×14px，白 7%，中线黄 16% | A `:528-536` |
| 十字准星 | 76px，十字线 1px faint，内环 1px 黄 35%，再内虚线圈（8px 间距）12s 自转 | A `:238-256` |
| 纸面 hatch | `135deg`，1px/26px，18s 漂移，右侧渐隐 | A `preview-rhine-line.html:19-20` |
| 纸面角 | 6×6 空心角，1px，四角 | A 同上 `:76-78` |
| 纸面实心角标 | 44×10，`135deg`，4px/4px，橙+墨 | A 同上 `:113` |

**切角**：本地终末地样片**一个切角都没有**，全是直角（推断：`index.html` 全文无 `clip-path`/`skew`）。斜切只出现在纸面系的 hatch 与「冲击版」的构图里（C `dsh-boot-metro/README.md:117-121`）。所以 zmd 的正确读法是**直角 + 斜向纹理**，不是「给所有卡片切一刀」；第三方设计语言把「每处斜切」列为失败模式（C https://ak-ui.yyj.moe/guide/design-language ）。

**层数上限（重要）**：本地线宽只有三档——**1px（结构线/网格/扫描线）、2px（只给 12px 的 L 形角标）、6px（危险带）**；没有 2px 以上的描边容器，带边框的容器只有一个（重播按钮 1px，A `:294`）。「工业感」来自**线宽统一 + 密度**，不来自粗细对比。**黄铺满全屏只允许发生一次**：收尾那 420ms 的扫屏（A `:271-274`），它不是背景，是转场。

**节奏配方（可直接抄的相对时间轴）**：0ms 底线 → 200/280ms 横线 → 340/420ms 竖线 → **480/560ms 危险条** → 500–680ms 角标 → 850–1060ms 四角 HUD → 780ms 起逐字标题（45ms/字） → 1000ms metabar → 1250ms 起日志（**150ms/条**） → 3400ms `READY` → 收尾三拍。读数到 100% 约 4.0s（6 段时长和 3580ms + 5×30ms 间隔 + 260ms 起跑），加上收尾的 1010ms，**整段 ≈ 5.0s**（A `:134-196,431,631,636-639,645-650`）。

**数字滚动**：本地样片**不做**滚动——每帧直接写 `textContent`（A `:578-589`），横向不抖全靠 `tabular-nums` 与补零。要滚动就只能是「定宽位 + 每 60–80ms 跳一格」，位数在整段里不得增减（推断，依据是所有读数都定宽补零，A `:469`）。

**故障闪烁与冲击帧**：本地样片**没有** glitch——唯一的「冲击」是 420ms 的黄底扫屏（A `:274`）。建议：要故障感就压到 **1–2 帧（16–32ms）的不透明跳变，一次事件不超过 3 跳**，并跟 `prefers-reduced-motion` 兜底（A `preview-rhine-line.html:29` 就是这么做的）。**推断**：zmd 的「工业」不靠抖动。

## 5. HUD 版式

**安全区三层**（A `index.html`）：58px 画线框 → 74px metabar 内缩 → 76px 内容起点。四角 HUD 宽 214px（上）/240px（下），间距 18px（`:192-196,187`）。

**结构（从上到下 / 从左到右）**
1. **顶部 metabar**：品牌名 → 终端号 → 协议版本 →（撑开）→ UTC 时钟 → 经纬度。10px、.18em、dim 色，`<b>` 用黄（`:322-330`）。
2. **左右四角块**：每块 = 9px 区块头（.34em、黄底下 1px 线）+ 4 行键值（`k` 列定宽 62px、dim 色）（`:186-191,340-355,368-382`）。
3. **中央主体**（偏右 11%）：kicker（黄、.68em）→ 超大 wordmark（96px/800/.1em/line-height .9）→ 分隔横线 → 副标题（9px/.36em）；右侧一条 260px 的 1px 黄渐变竖线（`:204-235`）。
4. **左下偏中**：日志流 300px 宽、9.5px、最多 11 行滚动（`:259-267,630`）。
5. **底部中**：示波器 300×84，带 15/14px 网格（`:80-85`）。
6. **左边缘**：14px 竖轨进度 + 41px 刻度 + 顶端悬浮读数（`:88-126`）。
7. **正中**：76px 十字准星（`:238-256`）。

**层级强弱（照抄这个顺序）**：主读数（大/黄/等宽）> 区块头（小/亮/超宽字距/带线）> 键值行（dim、等宽、定宽列）> 装饰线。**任何装饰的颜色不超过 dim 档**；黄只出现在读数、进度、角标、危险带四处，不出现在区块背景或正文（A 全文件成立）。

**信息密度**：4 角 × 4 行 = 16 条遥测 + 2 条 metabar（各 3–4 组）+ 11 行日志；同时动的元素 ≤ 6（进度、示波器、拓扑、时钟、条形图、扫描带）。日志 150ms 一条、保留 11 行，是「看得见在跑但不抢眼」的密度上限（A `:631,630`）。

## 6. 交互范式

| 交互 | zmd 式做法 | 来源 |
|---|---|---|
| 按钮（石墨） | 透明底 + 1px `rgba(255,255,255,.16)` 边框 + 10px/.2em 大写；hover **只改前景色与边框色**（200ms），不填色、不放大 | A `index.html:290-298` |
| 按钮（纸面） | 实色黑矩形 + 反白字；次级「更多」链接是灰底浅字，hover **前景与背景同时反转** | C https://ak-ui.yyj.moe/guide/official-site-study （方舟官网观察） |

| 悬停（列表/表格） | 整行实心强调底 + 墨字；链接只给下划线着色 | C（同上） |
| 跳过 | 任意点击/按键直接跳过开场，不做过渡队列 | C（第三方插件描述：`dsh-plugin.org` 的 `dsh-endfield-theme`） |
| 状态推进 | 一条状态文本单点推进 `INITIALIZING → LOADING CORE → SYNCING GRID → MOUNTING → READY`，**不并列多个 spinner** | A `:636-639` |
| 焦点 | 2px 实色 outline + 1px offset，且不被裁切容器切掉 | C（ak-ui 契约；本地样片无键盘流） |

**哪些交互「有 zmd 味」**：单点状态文本推进、边框亮起式 hover、读数贴轨、跳过后立刻结束、按钮永远直角且不发光。**没味**：弹性回弹、涟漪、悬停放大、hover 时整块变黄、loading 转圈。

## 7. 正反例

**像 zmd（6 条，均可指到源码）**
1. 58px 内缩的 1px 四边线框 + 12px/2px 的 L 形四角（A `index.html:134-151`）。
2. 9px、`.34em` 的区块标题，下面压 1px 底线（A `:188-191`）——标题靠**字距与线**立起来，不靠字号。
3. 14px 左侧竖轨：黄填充 + 41px 黑刻痕 + 顶端悬浮大读数（A `:88-126,436-441`）。
4. 45°、9/9px 的黄黑危险条纹，只做上下两条 6px 带，透明度 .85（A `:155-162`）。
5. 逐字 18px 上移 + 8px 模糊、45ms 错峰的标题入场（A `:218-222,431`）。
6. （补）读数全部 `tabular-nums` + 补零 + 固定小数位（A `:113,469,583-589`）。

**不像 zmd（廉价赛博/通用件）**
1. 深底 + 青蓝描边 + 到处泛光——青蓝是明日方舟官网的信号色（`#19d1ff`，C https://ak-ui.yyj.moe/guide/official-site-study ），**不是终末地黄**。
2. 圆角卡片 + 柔和浮阴影（本地全直角，零 `border-radius`，除状态点/准星环）。
3. 每个元素都切角/编号/等宽/大写——ak-ui 把它列为失败模式（C：https://ak-ui.yyj.moe/guide/design-language ）。
4. 用 glow 代替层级：本地全程只有 1 处阴影（进度条 `box-shadow: 0 0 22px`，A `:95`）。
5. 满屏高对比扫描线 + 长时间 glitch 抖动：本地扫描线只有白 2.5%、1px/3px（A `:27`），且无 glitch。
6. 大面积铺黄（>10%）：实测黄像素占比约 2.5–5.5%（C 第三方统计）。

## 8. 给「国家电网 × zmd」的移植建议

> 前提：国网官方 VI 色值我**没有取到**（无外网、不能吸官网图）。请从官方 VI/SVG 源文件取值，不要从截图取色；下文用「国网绿」指代，不给 hex。

1. **绿只占一个语义槽，黄降级一个槽。** zmd 里黄是「信号/待确认/危险」；国网的绿是「认证/合规/运行正常」。建议：绿 = 状态正常与认证章，黄 = 读数与危险带；**同一元素不许双强调色**，两者相邻时中间垫 1px dim 线。（依据：单一强调色原则，A `:10` 全文件唯一强调色）
2. **圆形标识放进准星，不要放进中央。** zmd 的圆形只出现在「仪表/准星/状态点」（A `index.html:248-256`）。把国网圆形徽标做成 96–120px 的环内标识：外环 1px、内虚线环 8px 间距、中心留 12px 方块位——位置选右下角 HUD 之上，**中央主位留给主读数**（推断，依据 `:204-235` 主位被 wordmark 占据）。
3. **严谨网格用 64px 主网，别加密度。** 国网的「调度感」来自正交与等距，不是来自更多线。抄本地的双层网格（64px 白 4.5% + 16px 白 2.2%，A `:36-49`），但把 mask 收紧（主 25%→60%），并禁止在网格上再叠加斜 hatch——两者同屏会互相抵消。
4. **字体分工**：中文标签走 `--sans`（黑体族），编号/读数走 `--mono` 等宽，标题**不要用压缩体**——Bahnschrift 那套属于纸面宣传物（A `preview-rhine-line.html:10` 的用途是海报标题），调度台用它会像广告。
5. **危险条纹保持黄黑，不换成红绿。** 国网里红=禁止、绿=安全，但 zmd 的危险带是**黄黑工业警示**（A `:156-157`）；把国网绿塞进条纹会让「警示」变成「品牌装饰」。条纹只允许出现在 6px 高的边缘带，且全屏 ≤2 条。
6. **双模式交付**：深色调度台（默认，A `index.html` 全套 token）+ 纸面报表（B 取样 `splash-light.png` 的纸/墨/线）。同一套字号字距，只换底与反色；纸面模式下**国网绿必须下沉一档**才有对比（同理黄在纸底只有 1.07:1，C）。
7. **不要做的三件事**：把国网 logo 做成满屏发光背景；给圆形标识加旋转光圈；把「国家电网」四字做成压缩大写英文风 wordmark——zmd 的超大标题是**拉丁字标**（A `index.html:404` 的 `ENDFIELD`），中文进入该位置会直接露馅。
